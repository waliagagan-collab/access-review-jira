## 1. The app

Read in full: `manifest.yml`, every file under `src/`, `static/export/`, the tests, `README.md`.

### Checked and found right

- **Admin check.** All 11 resolvers are defined through `define`, which wraps each one in
  `adminOnly`: Jira is asked, as the calling user, for the global ADMINISTER permission, and any
  failure to confirm is a refusal. A test fails if a resolver is defined any other way. The export
  frame calls the same resolvers. The queue worker is not a resolver and serves no request.
- **Licence.** In production `startReview`, `setDecision`, `setDecisionsBulk`, `completeReview` and
  `reopenReview` are refused without an active licence, on the server as well as on the page.
  Reading, the evidence download, deleting and cancelling stay open. Development and staging are
  never blocked.
- **Scopes.** Seven, all read-only plus `storage:app`. Each one is used; the table in
  `listing.md` matches the manifest, and the Marketplace lists the same seven for 2.6.0. No egress,
  no remotes. The deploy reports the build as eligible for Runs on Atlassian.
- **Stored data.** Account IDs, group IDs and names, Jira product names and seat counts, activity
  bands or last-activity times, decisions, notes (up to 500 characters), and the account IDs and
  times of who started, decided, signed off and reopened. No names or emails; they are read from
  Jira when a page or file is built. 12 reviews kept; a signed-off one is never removed
  automatically.
- **Forge limits.** Stored values are split (64 user shards, groups in 250s, rows in 100s, 64
  decision shards). Slices stop at 240 s inside a 300 s function (Forge allows 900). A failed queue
  push pauses the run and the page resumes it. The retry handling matches Atlassian's current
  async events page: retries continue inside the retention window, with no fixed count.
- **The decision lock.** `keyPolicy: 'FAIL_IF_EXISTS'` exists in the installed `@forge/kvs` 2.0.7.
- **Evidence files.** Excel cells are written as text; CSV cells that start with `= + - @` get a
  leading apostrophe.
- **Error handling.** Every `invoke` on the page is caught and shown; a failed status poll does not
  blank the page.

## 7. Not changed, and why

- **A9, personal data reporting.** It needs the scope `report:personal-data`, which makes a major
  version that the production customer has to approve. Proposal: add the scope and a weekly
  scheduled trigger that reports the account IDs held in the kept reviews, and for a closed account
  replaces its ID in rows and decisions. Permissions & Access Review for Confluence already does
  this and can be the model. Until it ships, leave the Marketplace answer as it is and change both
  together. Gagan decides.
- **A10, the review table on large sites.** UI Kit's table has no sort callback, so a fix means the
  app's own sorting and paging, which changes how the table behaves and has to be tried in a
  browser on a seeded review of about 5,000 rows. Unchanged since 10 November.
- **A11, moderate npm audit findings.** They sit inside Forge's own packages. The bar is no high or
  critical, and there are none.
- **A12, a confirm before a new snapshot removes an open review.** A behaviour change on the start
  button that I could not try in a browser. Proposed for the next round.
- **A13, Forge package updates.** `npm update` would move six packages a minor version. With no
  browser to check the page afterwards, and nothing broken, I left them.
- **A14, "every user" on the page.** True in practice, and changing it would make one more
  screenshot out of date for no gain.
- **Em dashes in a few status lines** ("You can leave this page — the snapshot continues"). Plain
  enough; left.
- **The old working images** in `marketplace/assets/2026-10-13/`. They are the record of what is
  live.
- **The website.** Outside this audit. The privacy policy sentence in L11 is the one to fix first.
- **Price.** Owner's call (L12).
- **The live checks listed on 10 November** (the download following the open review, `updatedBy`
  as the app, the work-log fallback, the lock under fast clicking) are still not done. No browser.
